# 2a. Agenda : synchro Google et Gmail, catégories, visio

Périmètre : instantané poussé par Claude (`push-agenda.mjs`), mails, renvoi vers Google, Aurion, Outlook, liens de visio, catégories d'agenda. L'affichage (frise, blocs, glisser-déposer) est dans `D\agenda-affichage.md`. (`D\` = `docs\claude-branches\`, voir la racine du projet.)

1. Le site n'a aucun accès direct à Google (pas d'OAuth, pas d'appel réseau) : les connecteurs Agenda/Gmail n'existent que dans les sessions Claude.
2. En session, Claude lit l'agenda (aujourd'hui + 98 jours, toute la frise ; `endTime` explicite et pagination suivie, sinon le connecteur s'arrête à 7 jours et le script purge le reste : incident du 2026-10-06) et les non lus, écrit un JSON `{ events, mails }` (format en tête de `scripts/push-agenda.mjs`) et lance `node --env-file=.env.local scripts/push-agenda.mjs <fichier.json> [--dry-run]`.
3. Le script upsert dans `calendar_events` et `mail_items` (RLS sans policy anon, expéditeur/sujet/date seulement) puis supprime les lignes absentes du fichier : ce sont des caches. Seuls les événements `origin = 'google'` **pas encore terminés** sont purgés (ceux créés sur le site, `origin = 'local'`, jamais ; un événement fini reste en base comme historique, depuis le 2026-10-06) ; 50 mails au plus. Chaque mail porte `source` (`gmail` ou `edhec`) et `unread`. Règle EDHEC : libellé Gmail EDHEC, ou expéditeur / destinataire en `edhec.com` ; sinon `gmail`. `colorId` Google (facultatif) va dans `calendar_events.color_id` (`supabase/agenda-links.sql`), qui pointe vers une **catégorie** éditable sur le site (nom, couleur, type `plage` ou `tache`, voir point 9) : les 3 clés par défaut `11`/`9`/`6` sont celles poussées par Google, `9` (« Autre événement ») sert de repli (colonne absente, couleur absente ou catégorie supprimée). Un conflit (`buildWeek().conflicts`, compteur « N conflit(s) » de l'agenda) n'oppose que deux catégories du même type qui se chevauchent : une tâche posée sur une plage est volontaire, jamais un conflit.
4. L'accueil les affiche (`components/AgendaPanel.js`, `components/MailsPanel.js`, logique dans `lib/home.js`, testée par `scripts/check-home.mjs`) (rien n'est en direct ; l'agenda n'affiche plus l'âge de la synchro, les mails gardent leur pied « Mis à jour il y a X » = max de `synced_at`). Mails : **une seule liste** (les deux boîtes fusionnées, source `gmail` = `thibautmartin04@gmail.com`, source `edhec` = `thibaut.martin95429@edhec.com`), en tri strict par date décroissante, une ligne par mail (expéditeur, objet, heure ou date), étiquette « EDHEC » sur les mails `edhec`, la ligne entière ouvre le mail dans Gmail ; non lus en gras côté Gmail seulement (EDHEC : ni gras ni compteur, il le lit dans Outlook) ; lecture seule (on les traite dans Gmail).
5. **Renvoi vers Google** : un bloc `google` déplacé prend `calendar_events.pending_move = true` (`supabase/agenda-moves.sql`) et affiche « À renvoyer vers Google » (et « Renvoi » sur le bloc). `push-agenda.mjs` ne l'écrase ni ne le purge tant que c'est `true`. En session, Claude lance `node --env-file=.env.local scripts/push-agenda.mjs --pending` (JSON `id, title, starts_at, ends_at`), écrit ces heures dans Google Agenda, puis `node --env-file=.env.local scripts/push-agenda.mjs --ack <id1,id2>` (remet `false`) ; la synchro suivante reprend l'événement tel que dans Google. Colonne absente : l'affichage marche, un déplacement renvoie « exécuter supabase/agenda-moves.sql ».
6. **Import Aurion** : un cours douteux (horaire ou titre perdu à l'extraction) reste « à reconfirmer » et n'entre pas dans l'agenda avant confirmation ; un événement en journée entière s'envoie en UTC (`allDay`, fin exclusive), sinon il glisse d'un jour (règle de Thibaut, 2026-09-19).
7. **Boîte Outlook.com perso** : elle refuse IMAP et l'enregistrement d'une app OAuth (AADSTS16000) ; la lire dans le navigateur intégré ou proposer un transfert vers Gmail (règle de Thibaut, 2026-09-19).
8. **Liens de visio** (demande de Thibaut, 2026-10-19 : les liens reçus par mail rattachés aux événements, un clic propose de lancer la réunion) : `lib/meeting.js` (fournisseurs Meet, Teams, Zoom, Webex, Jitsi, Whereby, Blackboard Collaborate ; testé par `scripts/check-meeting.mjs`). Stockage `dashboard_settings` clé `agenda_meeting_links` = `{ [eventId]: { url, src: google|mail, at } }`, sans colonne ni SQL, pour qu'un lien trouvé dans un mail survive aux synchros. Écrit par `push-agenda.mjs` (champs `meeting_url` / `meeting_source` des événements, ou `--meetings <fichier>` pour des liens seuls) ; repli : URL de visio écrite dans le lieu. Lu par `lib/cockpit-data.js` (`event.meeting_url`) : bouton « Rejoindre la réunion (Teams) » dans le détail de l'agenda. Le Bureau Cadran importe le même module (`https://cadran-lib.local/meeting.js`) : un fournisseur ajouté ici entre aussi dans la liste blanche `openurl` de son hôte. Le rattachement mail vers événement est fait par la routine `refresh-dashboard-agenda-mails` (étape 1 bis).
9. **Catégories d'agenda** (bouton « Catégories » du panneau Agenda) : `dashboard_settings` (clé `agenda_categories`, aucune table dédiée) porte une liste `{ key, name, color, kind }`, `kind` = `plage` ou `tache` (`lib/home.js`, `resolveCategories`/`categoryOf`, Server Actions `saveCategory`/`deleteCategory`/`moveCategory` dans `app/edit-actions.js`, UI `components/CategoryEditor.js`). Les 3 catégories par défaut (clés `11`/`9`/`6`, les colorId Google) se renomment et se recolorent mais ne se suppriment pas ; supprimer une catégorie personnalisée repasse ses événements sur `9`. Le formulaire d'événement (`components/AgendaPanel.js`) choisit la catégorie dans cette liste et peut la renommer/recolorer sans quitter l'agenda (`CategoryPicker`). La couleur ne part jamais vers Google. Un bloc Google rangé dans une catégorie créée sur le site (clé `c-…`) la garde à la synchro (`scripts/push-agenda.mjs` ne l'écrase pas) ; passé sur `11`/`9`/`6`, il suit la couleur Google à la synchro suivante. Depuis le 2026-10-08 la couleur d'une catégorie ne colore plus les blocs de l'agenda (ils suivent leur type, voir `D\agenda-affichage.md` point 3) ; la catégorie garde son nom, son type `plage` / `tache` (couche du bloc, travail ou courte, conflits) et sa place dans le formulaire d'événement. « Catégories » s'ouvre depuis le bouton « + » de l'agenda (`CategoryEditor` piloté par `open` / `onClose`, ou seul avec son propre bouton). Le **type de chaque bloc** se corrige dans le détail (menu « Type », clé `agenda_kind_overrides`, `D\agenda-affichage.md` point 3).
